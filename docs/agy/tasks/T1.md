# T1：打点的数据模型、纯逻辑、本地存储

背景：先完整阅读 `docs/agy/plan.md`（尤其"数据模型""分层""云端同步-共同规则"），以及 `AGENTS.md`、`.agents/STYLE_GUIDE.md`、`apps/monkey/AGENTS.md`。

## 要做什么

1. `apps/monkey/src/utils/markers/types.ts`：按方案定义 `Marker`、`MarkerDoc`（用 `type`，不用 `interface`）。
2. `apps/monkey/src/utils/markers/core.ts`（可按需拆文件），全部为纯函数、不可变更新、无 DOM / 网络 / 存储依赖，时间由参数传入（`now: number`），便于测试：
   - `createDoc(meta)`、`addMarker(doc, { time, label?, endTime? }, now, id?)`、`updateMarker(doc, id, patch, now)`、`removeMarker(doc, id, now)`（写墓碑 `deleted: true`）。
   - `visibleMarkers(doc)`：去掉墓碑并按 `time` 升序。
   - `findPrevMarker(markers, currentTime, tolerance = 2)` / `findNextMarker(markers, currentTime)`：上一个的规则——若当前位置距离"当前所在打点"超过 tolerance 秒，则回到该打点；否则回到再前一个。
   - `buildSegments(markers, segmentSeconds, duration?)`：片段为 `[time, endTime ?? time + segmentSeconds]`，按 duration 截断，重叠或相接的片段合并，返回升序 `{ start, end }[]`。
   - `nextSegmentAction(segments, currentTime)`：返回 `{ type: 'stay' } | { type: 'seek', time } | { type: 'ended' }`，供精华模式使用（在片段内→stay；在片段外→seek 到后面最近片段的 start；后面没有片段→ended）。
   - `mergeDocs(local, remote)`：按 `id` 合并，`updatedAt` 大者胜（相等时保留 local），墓碑参与合并；`doc.updatedAt` 取两者较大值；任一侧为空时返回另一侧。
   - `pruneTombstones(doc, now, maxAgeMs = 30 天)`。
   - `serializeDocs(docs)` / `parseDocs(text)`：导出导入格式 `{ v: 1, docs: Record<pickCode, MarkerDoc> }`；`parseDocs` 对非法输入抛出带可读信息的错误，并丢弃字段不合法的打点（项目已依赖 zod，可用）。
   - `formatMarkerTime(seconds)`：`H:MM:SS` 或 `M:SS`。
3. `apps/monkey/src/utils/cache/markerStore.ts`：`class MarkerStore extends CacheCore<MarkerDoc>`，仿照同目录 `subtitlePreference.ts`（独立 storeName、`enableQuotaManagement: false`），提供 `getDoc(pickCode)`、`saveDoc(doc)`、`getAllDocs()`、`replaceAll(docs)`，导出单例 `markerStore`，并在 `utils/cache/index.ts` 中导出。
4. 单元测试放在 `apps/monkey/src/utils/markers/__tests__/*.test.ts`，覆盖上面每个函数的正常与边界情况（空文档、同一时间多个打点、墓碑、片段重叠、duration 截断、合并冲突、非法导入）。
5. 新增 changeset：`.changeset/markers-core.md`（`'@115master/monkey': patch`，一句话描述）。
